# Корпус «Существительные и прилагательные»

Этот каталог — редактируемый источник данных для генерации статических упражнений. Файлы из `public/content/` будут производными и не должны становиться источником истины.

## Уровни публичных тематических упражнений

- `practice/` — редактируемый корпус из 2894 упражнений и вложенных индексов,
  перенесённый из `public/content/practice/single_choice/adjectives-nouns/`.
- `practice-levels.json` — явные методические оценки A1/A2 для всех форм
  прилагательных/определителей и существительных из `correctAnswer`.
- Производные каталоги: `public/content/practice/single_choice/adjectives-nouns-a1/`
  и `adjectives-nouns-a2/`. Меню содержит два раздела вместо прежнего общего.

A1 назначается, только если оба компонента относятся к A1; наличие хотя бы
одного компонента A2 даёт A2. Классификация — методическая оценка для этого
приложения, а не официальная граница CEFR. A1 включает базовую бытовую лексику,
семью, частые профессии, покупки, еду, путешествия, цвета, размеры и простые
определители. A2 — расширенную, абстрактную и менее частотную лексику. Редкие
слова остаются в расширенном A2, поскольку этот шаг не удаляет задания.

Учитываются только компоненты `correctAnswer`, не `prompt` и не `wrongAnswers`.
Составные существительные (`κινητό τηλέφωνο`, `στάση λεωφορείου`) оцениваются как
лексические выражения. Числительные и местоимения занимают место прилагательного
в таблице уровней. Для `ο οποίος` / `όποιος` учитывается местоимение, а не глагол
придаточной части; для `δικός μου` — всё притяжательное сочетание. Если в исходном
ответе только существительное (`το μετρό`), уровень определяется по нему.
В конструкциях `γυναίκα αστυνομικός` учитываются оба именных компонента.

Таблица хранит наблюдаемые формы явно, включая женский род, множественное число
и варианты написания. Это позволяет не угадывать леммы при каждой генерации.
Новые формы без оценки вызывают ошибку, а не автоматически попадают в A2.
При пересмотре уровня слова обновляйте все его формы в таблице согласованно.
Существующие `lexicon-candidates.json` и текстовые словари использовались для
сопоставления форм, но их импортированные метки уровня не являются правилом
этого разбиения (см. также `ATTRIBUTION.md`).

После редактирования `practice/` или `practice-levels.json`:

```bash
npm run generate:nouns-adjectives-levels --prefix webapp
npm run validate:content --prefix webapp
npm run test --prefix webapp
```

Команды выше запускаются из корня репозитория. Генератор сохраняет содержимое
заданий и их ID; тематические ID получают суффикс уровня в префиксе, а пустые
ветки исключаются из меню. Исходные формулировки, переводы и естественность
словосочетаний этим шагом не исправляются.

**Важно:** старые `nouns.json`, `adjectives.json`, `pairings.json` и команда
`generate:nouns-adjectives` ниже относятся к отдельной начальной модели корпуса.
Они не генерируют нынешний тематический раздел `adjectives-nouns-*`.

## Файлы

- `themes.json` — темы, к которым относятся существительные.
- `nouns.json` — род и формы именительного падежа существительных.
- `adjectives.json` — шесть форм прилагательных и тип построения словосочетания.
- `pairings.json` — вручную подтверждённые естественные сочетания и их переводы.
- `lexicon-candidates.json` — импортированный инвентарь A1+A2 для последовательной ручной проверки.
- `ATTRIBUTION.md` — источники данных и условия лицензирования.

## Типы конструкции

- `article-adjective`: `ο καλός φίλος` — артикль перед прилагательным.
- `determiner-article`: `αυτός ο φίλος` — артикль между определителем и существительным.
- `articleless-determiner`: `κάποιος φίλος` — определитель без артикля.

## Правила данных

- Идентификаторы записываются в `kebab-case` и не меняются после публикации.
- `lemma` хранит словарную форму; у существительного она включает артикль.
- Если у существительного нет естественного множественного числа, `forms.plural` и `translations.plural` равны `null`.
- В `pairings.json` наличие перевода для числа означает, что сочетание проверено и естественно в этом числе.
- Перевод в паре относится ко всему словосочетанию, а не только к существительному.
- Второстепенные варианты написания не создаются как отдельные лексемы.

## Команды

```bash
npm run generate:nouns-adjectives
npm run validate:nouns-adjectives
```

Для повторного импорта рабочего инвентаря нужны текстовые версии глоссариев и JSONL-выгрузка Kaikki:

```bash
node scripts/import-a1-a2-lexicon.mjs \
  --a1-text /path/to/klik-a1.txt \
  --a2-text /path/to/klik-a2.txt \
  --kaikki-jsonl /path/to/kaikki-greek.jsonl \
  --output content-source/nouns-adjectives/lexicon-candidates.json
```

Вторая команда проверяет покрытие всех форм, размеры частей и соответствие публичных JSON исходному корпусу. Она также запускается в составе `npm run validate:content`.

Начальные записи нужны для проверки модели. Полный корпус A1+A2 будет добавляться тематическими партиями.
